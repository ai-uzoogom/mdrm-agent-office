브라우저 데이터 변경 검증은 테스트 요청에만 수정된 모듈을 제공했습니다. 실제 `src/data.js`에는 요청받은 세 이슈와 원래의 현재·예정 릴리스가 남아 있습니다.

숨은 탭 검증은 `document.hidden` 값을 위조하거나 가짜 이벤트를 보내지 않았습니다. 테스트 전용 Chrome에서 페이지 디버거를 분리하고 실제 탭을 전환한 뒤 `visibilitychange` 기록을 회수했습니다. 전투가 진행 중인 별도 관찰에서도 숨김 직전·복귀 시 프레임 134, 진행 시간 약 2.226초가 동일했습니다. 자동화 브라우저의 강제 가시성 유지가 결과를 가리지 않도록 검증 스크립트에 이 절차를 반영했습니다.

캐릭터 해상도 보완 후 1280px·390px / DPR 2와 일반 DPR 1에서 장면, 썸네일, 클릭 좌표, 반응형 배치와 성능을 다시 확인했습니다. 화면 밀도를 반영하는 캔버스와 가로 960px 렌더 상한을 적용했고, 최근접 필터와 기존 색상·레이아웃을 유지했습니다.

화면은 데스크톱 전체, 모바일 전체, 도감·개발진·용사단 탭을 직접 확인했습니다. 한글 글리프, 줄바꿈, 말풍선 겹침, 레이블 숨김, 테두리, 썸네일과 색상 일관성을 점검했습니다.

## 검증 범위

390px 결과는 데스크톱 Chrome의 모바일 뷰포트 검사입니다. 실제 휴대폰 GPU 성능과 iOS Safari·Firefox는 검사하지 않았습니다. 60fps 측정은 이 로컬 환경과 기본 3개 이슈 구성의 결과이며 다른 기기의 성능 보장은 아닙니다. 원격 배포 및 실제 MDRM 서비스 연결은 이 정적 페이지의 검증 범위에 포함되지 않습니다.

## 재실행

서버를 실행한 상태에서:

```sh
npm test
npm run test:browser
npm run test:visibility
```

`test:visibility`는 독립된 임시 Chrome 프로필을 만들고 검증 후 그 프로필과 브라우저를 정리합니다. 사용자 브라우저 프로필은 사용하지 않습니다.


## GitHub Pages 사전 검증

`npm run prepare:pages`로 51개 파일, 8.02 MiB의 정적 배포 파일을 생성했습니다. 실제 프로젝트 사이트와 같은 `/mdrm-agent-office/` 하위 경로에서 1280px·390px 화면, GLB·PNG·폰트 로딩, 클릭, 탭, 데이터 반영, 모션 줄이기를 확인했습니다. 콘솔·HTTP 오류와 가로 넘침은 없었고, 평균 및 1초 구간 최저 60fps를 기록했습니다.

자동 배포 워크플로를 준비했으며, 웹사이트에는 런타임 파일만 포함합니다. 소스 저장소에서도 `node_modules/`, `test-results/`, `_site/`를 제외했습니다. 이 검증은 로컬 사전 검증이며 GitHub에 실제 공개한 결과는 아닙니다.
