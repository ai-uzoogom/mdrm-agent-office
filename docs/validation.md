## 검증 범위

390px 결과는 데스크톱 Chrome의 모바일 뷰포트 검사입니다. 실제 휴대폰 GPU 성능과 iOS Safari·Firefox는 검사하지 않았습니다. 60fps 측정은 이 로컬 환경과 기본 3개 이슈 구성의 결과이며 다른 기기의 성능 보장은 아닙니다. 실제 MDRM 서비스 연결은 이 정적 페이지의 검증 범위에 포함되지 않습니다. GitHub Pages 공개 환경은 아래 별도 항목에서 검증했습니다.

## 벽 표지판·칠판 글자 부착 보완

벽 표지판과 릴리스 보드 제목을 화면 정면을 향한 라벨에서 각 3D 표면에 연결된 HTML 면으로 변경했습니다. 정사영 카메라로 면의 세 꼭짓점을 투영해 CSS 행렬을 계산하므로 글자와 배경 전체가 벽·칠판의 방향, 위치, 크기를 따릅니다. 개발실·서버실 표지판은 같은 높이에 맞추고 회의실 표지판은 창문과 칠판 사이의 빈 벽에 배치했습니다.

1280px·900px·600px에서 실제 렌더를 확인했고 390px에서는 기존처럼 표면 라벨이 숨겨집니다. 브라우저 회귀 검증에서 양쪽 벽의 ±30° 기울기, 창 크기 변경, 칠판 제목과 말풍선의 겹침 방지를 확인했습니다. 캐릭터 클릭, 자동 진행, 모션 줄이기와 데이터 변경 검증도 통과했으며 로컬 Chrome 평균 60.1fps, 완전한 1초 구간 최저 60fps였습니다. 실기기 모바일 검증은 포함하지 않습니다.

## 사무실 확대·이동

100~300% 확대·축소, 전체 보기 복귀, 확대 화면 드래그와 방향 버튼을 추가했습니다. 키보드 `+`·`−`·방향키·`0`과 Ctrl/Command+휠도 지원합니다. 일반 휠은 페이지 스크롤을 유지하고, 드래그 종료가 캐릭터 클릭으로 처리되지 않도록 구분합니다. 모션 줄이기 상태에서는 화면만 다시 그리며 자동 진행은 정지 상태를 유지합니다.

로컬 Chrome에서 확대 상한·하한, 이동 경계, 포인터 중심 휠 확대, 확대된 용사 클릭, 벽·칠판 글자의 동시 확대, 창 크기 변경 후 배율 유지를 검증했습니다. 1280px·390px의 실제 렌더를 확인하고 375px 세로·844px 가로 화면 및 터치 드래그를 Chrome에서 모사했습니다. 버튼은 44px 이상의 터치 영역을 유지하며 가로 넘침이 없습니다. 콘솔·페이지·HTTP 오류 0, 데이터 단위 테스트 7/7, 기존 브라우저 검증 통과, 기본 배율 자동 진행 평균 60fps·완전한 1초 구간 최저 60fps입니다. 터치는 모사 검증이며 실제 휴대폰은 미검증입니다.


## 슬라임을 Kenney 유령으로 교체

Graveyard Kit 5.0의 `character-ghost.glb`, 참조하는 `Textures/colormap.png`, CC0 라이선스를 포함했습니다. 원본 파일 바이트를 유지하고 SHA-256을 에셋 목록에 기록했습니다. 낮음 등급은 꼬마 유령, 보통 등급은 유령이며, 도감 썸네일에서도 작은 크기를 유지합니다. 등급 색상과 이슈 등급은 기존 값을 유지합니다.

원본 `idle`·`walk`·`attack-melee-right` 클립을 연결하고 유령이 지면 위에서 부유하도록 했습니다. 근접 접근·넉백 중에도 높이를 유지하며 슬라임 찌그러짐은 제거했습니다. 로컬 Chrome에서 장면·패널·이력·도감·클릭 설명, 추가 이슈의 꼬마 유령, 등급 변경, 퇴치 처리와 모션 줄이기를 검증했습니다. 1280px·390px 렌더와 900px 경계에서 가로 넘침·콘솔·페이지·HTTP 오류가 없었습니다. 실제 휴대폰 및 iOS Safari는 미검증입니다.


## 영웅 장비 결합과 일정 독려 담당

투구 밖으로 나온 원본 머리카락, 몸통 내부에 묻힌 갑옷, 손과 무관하게 움직이던 검·방패를 수정했습니다. 원본 머리 메시만 숨기고 투구와 갑옷 치수를 맞췄습니다. 검·방패의 손잡이는 원본 스킨의 손 위치에서 팔 관절에 연결했으며, 반격은 검을 전방으로 휘두르고 방어는 왼팔과 방패를 함께 들어 올립니다. 대기·반격·방어 자세에서 장비가 바닥 아래로 내려가지 않게 맞췄습니다.

Mini Characters의 여성 `character-female-e.glb`를 일곱 번째 직원인 **일정 독려** 담당으로 추가했습니다. 파일은 원본 그대로 포함하고 기존 팩의 텍스처·라이선스를 재사용하며 SHA-256을 기록했습니다. 원본 의상과 손에 연결된 확성기, 금색 말풍선, 정차 중의 소리 파장을 사용합니다. 개발실 중앙 통로를 이동하면서 세 독려 문구를 순환하고, 에이전트 패널·개발진 썸네일·상태 조회에도 표시됩니다.

- 독립 렌더: 대기·반격·방어 및 확성기 자세를 확대 확인했습니다. 4개 원본 애니메이션의 60프레임에서 손잡이가 관절을 따라 움직이며 고정 좌표를 유지했습니다.
- 보행: 23초 동안 세 직원의 가구 충돌 0, 정차 문구 9개 모두 관찰, 일정 독려 담당의 이동/확성기 사용 전환과 소리 파장 표시를 확인했습니다.
- 실제 숨김 탭: 프레임·시뮬레이션 시간 증가 0, 복귀 정상입니다. 모션 줄이기에서는 새 효과도 정지합니다.
- 단위 테스트 7/7 통과. 1280px·390px 및 반응형 경계, 확대·이동·클릭·탭·이슈 추가·등급 변경·퇴치 상태를 확인했습니다.

## 일정 독려 담당의 확성기 입 정렬

말할 때 확성기가 얼굴 옆에 머무는 자세를 수정했습니다. 원본 모델의 입 위치와 어깨·손·확성기 뒤쪽의 길이 관계를 이용해 팔 회전과 확성기 기울기를 함께 계산합니다. 손잡이는 손에 고정하고 원본 팔의 크기·길이는 변경하지 않습니다. 말이 끝나면 걷기 자세에서 소품을 들고 이동합니다.

세 방향에서 90개 애니메이션 프레임을 검사해 확성기 뒤쪽과 입 앞 기준점이 일치하는 것을 확인했습니다. 손에서 분리되거나 팔이 늘어나지 않았습니다. 입의 메시 표면에는 0.006 모델 단위의 여유를 둡니다. 확대 렌더와 1280px·390px 로컬 Chrome 검증을 통과했고, 자동 진행 평균·1초 구간 최저 60fps, 콘솔·페이지·HTTP 오류 0, 모션 줄이기 정지를 확인했습니다.


## 키보드 동작·화면 밀착·왼손 전진 방어

개발자 4명과 회의 담당자의 앉은 높이·의자 위치를 조정하고, 스킨의 실제 손·키보드 높이에 맞춰 양손을 번갈아 움직이도록 했습니다. 원본 팔 길이를 유지하며 상태에 따라 타이핑 속도를 달리합니다. 여성 원본 모델의 손 도구는 사무실 인스턴스의 해당 면만 제거했습니다. 원본 GLB·의상·손은 유지합니다.

모니터 4대와 노트북은 원본 LCD 내부 면의 좌표·기울기에 연결한 CanvasTexture를 사용합니다. 코드 입력·커서·테스트 출력·진행 막대와 회의 일정 목록이 변합니다. 노트북도 앉은 사람을 향하도록 방향과 위치를 맞췄습니다. 방패는 왼손 쪽 위치를 유지한 채 왼팔을 앞으로 내밀도록 수정했습니다. 윗부분을 먼저 전방으로 기울여 투구 아래를 지나며 얼굴을 가리지 않습니다. 드래곤 불꽃의 도착점은 방패 앞면을 따라갑니다.

- 손 검증: 50프레임 × 양손 × 5명, 총 500개 실제 스킨 메시 표본에서 키보드 관통 없음, 양손 이동과 키보드 범위·팔 길이 유지 확인. 모델별 가장 가까운 손과 키보드 간격은 약 0.024–0.097 월드 단위입니다.
- 화면 검증: 5개 화면 각각 중앙·네 귀퉁이에서 원본 GLB 면으로 레이캐스트했습니다. 모니터 간격은 약 0.00273, 노트북은 0.00122 월드 단위이고 법선 방향이 일치합니다. 5개 화면의 실제 픽셀 변화도 확인했습니다.
- 방패 검증: 세 방향의 전환·유지 동작 183개 자세에서 방패 삼각형과 투구 도형의 교차 0, 얼굴 중앙 가림 0, 왼손 위치·전방 도달·원래 팔 길이 유지를 확인했습니다. 대기 애니메이션에 따른 몸통·머리 움직임도 포함합니다. 기존 60프레임 장비 결합과 90프레임 확성기·입 정렬도 통과했습니다.
- 전체 회귀: 데이터 7/7, 브라우저 14개 항목, 확대·이동·터치 모사 통과. 1280px·390px와 900/901px 경계에서 오류·가로 넘침 0. 로컬 Chrome 자동 진행 평균 60fps, 완전한 1초 구간 최저 60fps.

## 앉은 직원의 책상 관통 보완

손 도달 거리만으로 앉는 위치를 정하던 계산에 실제 몸통·의상 메시의 경계를 추가했습니다. 개발 책상은 열린 쪽을 직원에게 향하게 하고 높이를 2.4 월드 단위로 맞췄습니다. 회의 테이블도 2.55로 조정하고 화면·키보드·소품을 상판에 함께 맞췄습니다. 몸통은 상판 앞 경계에서 0.15 이상 떨어뜨리고 의자는 같은 위치를 따릅니다. 무릎은 책상의 열린 아래 공간을 사용합니다.

개발자 4명과 회의 담당자 총 5명의 50개 프레임에서 몸통 경계 침범이 없고, 개발 책상의 12개 무릎 위치 레이캐스트에서 앞판이 통로를 막지 않음을 확인했습니다. 손 500개 표본의 키보드 도달·관통·타이핑 움직임과 원래 팔 길이, 화면 5개의 밀착·갱신 검증도 통과했습니다. 사용자 사진과 같은 390px / 225% 확대 화면을 Chrome에서 모사하고 실제 렌더를 확인했습니다. 실제 iPhone Safari 검증은 포함하지 않습니다.

## 모바일 글자 복원·회의실 의자 방향

560px 이하에서 이름표·방 이름·몬스터 등급·보드 글자를 일괄 숨기던 규칙을 제거했습니다. 모바일 100%와 225% 확대에서도 각 라벨이 표시되며, 말풍선은 이름표의 위치도 피하도록 했습니다. 개발실·회의실·서버실 명칭은 유지합니다.

## 회의실 의자 간격·고해상도·배포 캐시 보완

회의실 전체를 사진과 같은 시점으로 별도 렌더링해 네 의자의 좌석이 테이블을 향하는 것을 확인했습니다. 빈 의자 세 개는 추가로 0.5–0.6 월드 단위만큼 테이블에서 빼고, 메시 경계 기준 0.3 이상 간격을 검사합니다. 등받이 방향뿐 아니라 좌석과 테이블 사이 여백도 확인합니다.

렌더 상한은 가로 3840px·800만 픽셀·밀도 6배로 높였습니다. 기본 배율의 상세도 1.5배, 앱 배율의 제곱근, 브라우저 핀치 배율을 반영해 캔버스와 렌더 타깃을 함께 키웁니다. 1280px / DPR 2 기본 장면은 1752px에서 2628px로 늘었고, 썸네일은 384px에서 768px로 높였습니다. Chrome 모바일 모사에서 앱 확대 및 실제 visualViewport 배율 변경에 따른 버퍼 증가·복구를 검증했습니다. 800만 픽셀 제한도 검사합니다. 실제 iPhone Safari의 GPU 성능은 미검증입니다.

배포 파일에는 진입 스크립트와 모든 로컬 모듈, CSS에 동일한 콘텐츠 해시를 붙입니다. HTML만 새로 받고 하위 모듈을 이전 캐시에서 재사용하는 경우를 방지합니다. 버전이 붙은 실제 `_site/` 하위 경로에서 전체 브라우저 동작·데이터 변경 검증을 통과했습니다. 이 로컬 Chrome에서 평균·완전한 1초 구간 최저 60fps를 유지했습니다.

## 모바일 두 손가락 장면 확대

캔버스의 두 터치 좌표 사이 거리로 100~300% 확대·축소하고 중간 지점이 같은 내용 위에 머물도록 합니다. 두 손가락의 동시 이동은 장면 이동으로 반영합니다. 핀치가 시작되면 진행 중인 한 손가락 드래그를 정리하며, 놓기·취소 후의 상태를 복구하고 캐릭터 클릭으로 처리하지 않습니다. 움직이는 동안 렌더 버퍼 크기를 유지하고 놓은 뒤 상세도를 높여 잦은 GPU 버퍼 재할당을 줄입니다.

Chrome 모바일 터치 모사에서 실제 두 터치 포인트를 벌리기·오므리기·평행 이동·취소로 입력했습니다. 중간 지점 기준 확대, 100~300% 제한, 브라우저 전체 배율 1 유지, 잘못된 캐릭터 클릭 방지와 놓은 뒤 해상도 증가를 확인했습니다. 100%의 한 손가락 페이지 스크롤, 확대 후 한 손가락 드래그, 버튼·키보드·휠·모션 줄이기도 통과했습니다. 실제 iPhone Safari의 손가락 조작은 미검증입니다.
