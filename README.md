# MDRM AGENT OFFICE

MDRM 릴리스와 보안 패치 이력을 아이소메트릭 오피스로 표현하는 정적 웹페이지입니다. 2026-11-18에 java4shell 드래곤이 출현해 서버실이 다시 방어 중입니다. v4.7.4에서 퇴치한 몬스터 세 마리는 지하 1층 묘역에 남아 있습니다.

## 온라인에서 보기

[GitHub Pages에서 MDRM AGENT OFFICE 열기](https://ai-uzoogom.github.io/mdrm-agent-office/) · [소스 저장소](https://github.com/ai-uzoogom/mdrm-agent-office)

설치 없이 데스크톱·모바일 브라우저에서 바로 볼 수 있습니다.

## 실행

Python 3만 있으면 빌드나 패키지 설치 없이 실행할 수 있습니다.

```sh
cd mdrm-agent-office
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 **http://127.0.0.1:4173/** 을 엽니다. Node.js가 있으면 `npm start`도 같은 서버를 실행합니다. ES 모듈과 GLB 로딩을 위해 `file://` 대신 HTTP로 열어야 합니다.

Three.js, GLB, PNG 팔레트와 폰트를 모두 포함했습니다. 실행 중 CDN이나 외부 API 연결이 필요하지 않습니다. 정적 호스팅 시 `index.html`, `styles.css`, `src/`, `vendor/`, `assets/`를 같은 상대 경로로 복사하면 됩니다.

## 내용 변경

설정의 단일 진입점은 [src/data.js](src/data.js)입니다.

| 상수 | 변경 내용 |
| --- | --- |
| `PRODUCT` | 제품명, 현재 운영 버전 |
| `RENDERING` | 장면 해상도 상한, 화면 픽셀 밀도, 썸네일 해상도 |
| `GRADES` | 등급명, 형태명, 색상 |
| `ISSUES` | 이슈 추가·제거·이름·등급 |
| `RELEASES` | 버전 이력, 상태, 날짜, 포함된 이슈 ID |
| `CREW` | 직원 역할, 셔츠·화면 색상, 상태·정차 문구 |
| `AS_OF_DATE` | 푸터의 정보 기준일 |

`ISSUES`만 변경한 뒤 새로고침하면 장면의 몬스터, 사이드 패널, 작업 수, 이력, 도감에 함께 반영됩니다. 사용 가능한 등급은 `low`, `medium`, `high`, `critical`이며 ID는 중복 없이 지정합니다. 현재·예정 이력은 새 이슈를 자동으로 포함하고 건수도 다시 계산합니다.

`RELEASES` 항목의 `state`를 `released`로 변경하면 **그 항목의 `ids`에 포함된 이슈**가 서버실에서 사라지고 이력에 퇴치 완료로 표시됩니다. 새로 추가한 이슈를 해당 릴리스에서 해결할 때는 `ids`에도 추가합니다. 완료 이력은 명시된 ID만 유지합니다. 제품의 현재 버전 표시는 `PRODUCT.current`로 관리합니다.

날짜와 활동 로그는 모두 `Asia/Seoul` 기준입니다. D-day는 한국의 날짜 경계로 계산하며 발행 당일은 `D-DAY`, 이후는 `D+n`입니다. MDRM을 Linux 커널 기반 제품으로 설명하지 않으며, Linux CVE나 임의의 보안 이슈를 추가하지 않았습니다.

## 화면과 동작

- Three.js **0.160.0**을 로컬 고정하고 `GLTFLoader`, `SkeletonUtils.clone`, `AnimationMixer`를 사용합니다.
- 60 × 44 월드의 열린 디오라마에 두 벽과 낮은 칸막이, 개발실·회의실·서버실을 배치했습니다.
- 정사영 카메라의 방위각은 45°, 내려다보는 각도는 약 35.264°입니다.
- 모바일 장면에서 두 손가락을 벌리거나 오므리면 손가락 사이 지점을 기준으로 100~300% 확대·축소합니다. 두 손가락 이동도 지원하고, 확대 후에는 한 손가락으로 드래그할 수 있습니다. 100%에서 한 손가락 세로 이동은 페이지 스크롤을 유지합니다.
- 데스크톱은 장면 위에서 휠 위/아래로 확대·축소하고 클릭 드래그로 이동합니다. 100%에서도 이동할 수 있으며 화면을 덮는 확대·이동 버튼은 없습니다. 키보드 `+`·`−`·방향키와 `0` 또는 `Home`(전체 보기)도 사용할 수 있습니다. 장면 밖의 휠은 페이지 스크롤을 유지합니다.
- 화면 크기·픽셀 밀도·앱 확대·브라우저 핀치 확대를 반영해 렌더 해상도를 조정합니다. 상한은 가로 3840px·800만 픽셀·밀도 6배입니다. 1280px / DPR 2 기본 화면은 가로 2628px이며 확대 시 더 높아집니다. 기존 `NearestFilter`와 픽셀 스타일을 유지합니다.
- 안티앨리어싱은 꺼져 있습니다. DirectionalLight 1개, HemisphereLight 1개, `BasicShadowMap`을 사용합니다.
- 말풍선·이름·등급·벽 라벨·릴리스 보드 제목은 HTML입니다. 벽 표지판과 보드 제목은 해당 3D 객체에 연결된 면의 꼭짓점을 투영해 상자 전체의 위치·기울기·크기를 맞춥니다. 말풍선은 가까운 빈 위치를 찾고 벽 표지판과 보드 제목 영역도 피해 배치합니다.
- 직원은 모델의 실제 `sit`, `idle`, `walk` 애니메이션을 사용합니다. 보행 속도는 약 2.4 units/s입니다.
- 회의실 의자는 앉는 쪽이 테이블을 향하고 등받이는 바깥쪽을 향하도록 배치합니다.
- 책상의 열린 면을 직원 쪽으로 향하게 하고 앉은 체형에 맞춰 높이를 조정했습니다. 몸통은 책상 앞 경계 밖에 유지하고 무릎은 열린 아래 공간에 둡니다.
- 앉은 직원과 회의 담당자는 실제 손 위치·팔 길이·키보드 높이를 기준으로 양손을 번갈아 움직입니다. 타이핑 외의 점검·빌드 상태에서는 속도를 낮춥니다. 원본 여성 모델의 손 도구는 해당 사무실 인스턴스에서만 제거하고 의상·손과 원본 GLB는 유지합니다.
- 모니터 4대와 노트북 화면은 원본 모델의 LCD 면에 붙어 실제 기울기와 크기를 따릅니다. 코드 입력·커서·테스트 출력·진행 막대·일정 목록을 상태에 맞게 갱신하며, 숨긴 탭과 모션 줄이기에서는 손과 화면 모두 멈춥니다.
- 일정 독려 담당은 Mini Characters의 여성 `character-female-e`입니다. 개발실의 중앙 통로를 오가며 확성기를 들고 금색 말풍선과 소리 파장으로 진행 상황을 확인합니다. 말할 때는 입 위치를 기준으로 어깨와 확성기 각도를 계산하여 좁은 뒤쪽이 입 앞에 오도록 합니다. 손잡이 연결과 원래 팔 길이를 유지합니다. 패치 발행 후에는 “모두 수고했어요!”, “패치 발행 완료!”, “커피 한잔하고 가요!”를 순환합니다. 정차 문구는 `CREW`에서 바꿉니다.
- 용사의 투구는 원본 머리 메시를 가려 머리카락이 튀어나오지 않게 했습니다. 검·방패는 스킨의 손 위치에 연결하고 공격·방어 시 팔을 따라 움직입니다. 장비는 대기 자세에서도 바닥 위에 유지됩니다.
- 브레스 방어 시 방패를 왼손에 둔 채 왼팔을 앞으로 내밉니다. 방패의 아래 기울기는 약 7도로 제한하고 왼팔을 더 전방으로 내밀어, 방패를 세운 채 투구와 간격을 확보합니다. 불꽃의 도착점은 방패 앞면을 따라갑니다.
- 낮음·보통 등급은 Graveyard Kit의 흰 유령 모델을 사용합니다. 낮음은 작은 `꼬마 유령`, 보통은 `유령`이며 도감에서도 크기를 구분합니다. 원본의 `idle`·`walk`·`attack-melee-right` 애니메이션과 부유 이동을 사용하고, 장면·패널·이력·도감·활동 로그에 같은 이름과 모델을 반영합니다.
- 근접 전투, 검 휘두르기, 넉백, 스파크, 드래곤 브레스와 방패 동작은 하나의 프레임 시간 기반 상태 머신으로 진행합니다. 별도의 전투 타이머가 백그라운드에서 계속 실행되지 않습니다.
- 숨김 상태에서는 `requestAnimationFrame`을 취소하고 시뮬레이션 시간이 멈춥니다. 복귀 시 누적된 시간을 한꺼번에 진행하지 않습니다.
- `prefers-reduced-motion: reduce`에서는 초기 정지 화면과 고정 상태를 표시합니다. 창 크기 변경·상태 조회·화면 확대 및 이동에 필요한 재렌더만 수행합니다.
- 활동 로그는 최신 7개를 유지하고 새 항목만 `aria-live="polite"`로 알립니다. 상태 버튼으로 키보드 접근도 가능합니다.
- 탭은 방향키·Home·End를 지원합니다. 썸네일은 동일한 정사영·조명 팔레트로 768 × 768 오프스크린 렌더한 실제 3D 정지 이미지입니다.

## 채택한 디자인

사용자 지정 RPG 시안을 유지합니다. 어두운 페이지 위에 파란 RPG 창, 3px 크림 테두리, 픽셀 컷 모서리를 적용했습니다. 금색은 다음 릴리스와 용사, 청록은 방어·펫, 등급별 색은 몬스터에 일관되게 사용합니다.

모든 UI 토큰은 [styles.css](styles.css)의 `:root` 한 곳에서 관리합니다. 영문 제목은 `Press Start 2P`, 한글은 `Nanum Gothic Coding`입니다. 둘 다 로컬 폰트입니다. 본문은 촘촘한 작업 화면을 유지하면서 장면이 가장 넓은 영역을 차지합니다.

900px 이하에서는 장면과 패널을 한 열로 배치합니다. 작은 화면에서도 직원 역할·방 이름·몬스터 등급·보드 글자를 표시합니다. 말풍선은 이름표와 방 표지판 영역을 피해 배치합니다. 모바일 좌우 여백은 16px입니다. 단일 다크 테마입니다.

## 검증

실행 중인 로컬 서버에서 다음 명령을 사용합니다. Node.js 22 이상과 개발 의존성은 테스트에만 필요합니다.

```sh
npm ci --ignore-scripts
npm test
npm run test:browser
npm run test:view
npm run test:equipment
npm run test:coffee
npm run test:workstations
npm run test:visibility
```

브라우저 테스트는 기본적으로 macOS의 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`을 사용합니다. 다른 환경에서는 `CHROME_PATH`를 지정합니다. 서버 주소는 `OFFICE_URL`로 변경할 수 있습니다. `test:view`는 확대·이동·리셋, 확대 상태의 캐릭터 클릭과 글자 정렬, 키보드·휠·터치 모사, 작은 화면 배치를 검사합니다. `test:equipment`는 60개 애니메이션 프레임의 손·장비 결합, 투구, 장비의 바닥 간섭, 공격·방어 자세와 새 직원의 소품을 검사합니다. `test:coffee`는 실제 사무실 운영 지원 캐릭터의 보행·대기 1,800프레임에서 손 스킨과 컵 손잡이의 밀착, 컵 수직·팔 길이, 네 정차 지점을 확인합니다. `test:workstations`는 몸통 경계·무릎 공간과 모바일 225% 확대, 500개 실제 손 메시 표본의 키보드 간섭·움직임·팔 길이와 5개 화면의 원본 LCD 밀착·픽셀 변화를 검사합니다. `test:visibility`는 테스트 전용 창에서 세 직원의 전체 보행 경로, 독려 문구·소리 효과와 정지·복귀 조건을 검사합니다.

`.github/workflows/pages.yml`은 `main` 브랜치에 push하거나 Actions에서 수동 실행하면 정적 페이지를 배포합니다. 저장소의 **Settings → Pages → Source**는 **GitHub Actions**를 선택합니다.

```sh
npm run prepare:pages
```

생성된 `_site/`에는 `index.html`, `styles.css`, `src/`, `assets/`, `vendor/`와 `.nojekyll`만 포함됩니다. 문서·테스트·개발 의존성은 웹사이트 배포 파일에 포함하지 않습니다. 모든 런타임 경로가 상대 경로이므로 `https://<owner>.github.io/mdrm-agent-office/` 형태의 프로젝트 사이트에서도 동작합니다.

워크플로는 GitHub의 공식 Pages 액션을 커밋 SHA로 고정하며, 별도 배포 비밀번호나 개인 토큰 없이 저장소의 `GITHUB_TOKEN`과 OIDC를 사용합니다. 이 프로젝트의 소스 저장소와 GitHub Pages 사이트는 공개 상태입니다. `main`에 변경을 push하면 자동으로 사이트가 갱신됩니다.

배포 시 진입 스크립트·모든 로컬 모듈·CSS에 같은 콘텐츠 버전을 붙여, 새 페이지에서 이전 캐시의 의자 배치나 설정을 재사용하지 않게 합니다. 이 처리는 `_site/`에만 적용합니다.

## 퇴치 묘역

지하 1층에 가장 최근에 패치된 몬스터의 무덤을 최대 6기까지 배치합니다. Kenney Graveyard Kit의 둥근 묘비와 무덤 테두리를 사용합니다. 묘비를 누르면 이력의 해당 항목으로 이동하고, 서버실 패널의 **퇴치 묘역 · 패치 기록** 버튼으로도 목록을 열 수 있습니다. 이전 기록은 이력에 남습니다.

현재 v4.7.4의 발행일은 2026-11-13이며 php2shell, Java 인증서, nginx 세 건을 기록했습니다. 무덤은 `RELEASES`의 발행 완료 항목에 명시된 이슈만 표시합니다. 모든 이슈가 완료되면 균열 봉인과 용사 휴식 상태가 나타납니다.


### 층 이동

처음에는 1층 오피스가 활성화되고, 아래에는 어두운 지하 묘역이 보입니다. 어두운 지하층 또는 화면 아래 B1 버튼을 누르면 650ms 동안 1층이 위로 빠지고 지하층이 올라옵니다. 1F 버튼으로 반대 방향으로 돌아옵니다. 버튼은 캔버스 바깥에 두어 장면을 가리지 않습니다. PageDown/PageUp 키도 지원합니다.

묘비는 지하층에서 선택할 수 있고, 비활성 층의 이름표·말풍선과 클릭은 차단합니다. 확대·이동 상태를 층별로 기억하며, 지하층은 묘비를 읽기 쉽도록 125%로 시작합니다. 모바일의 작은 묘비에는 44px 터치 범위를 제공합니다. 빠른 연속 선택은 현재 위치에서 방향을 바꾸며, 모션 줄이기 또는 숨겨진 탭에서는 즉시 선택한 층으로 전환합니다. 기존 무료 Kenney 에셋을 재사용하며 추가 외부 에셋은 없습니다.

`npm run test:floors`는 지하층 직접 클릭, 양방향 애니메이션, 연속 선택, 층별 시점 복원, 묘비별 기록 이동, 키보드·모션 줄이기, 모바일 터치와 확대를 확인합니다.


## 화면 디자인 · 2026-11-16

사용자가 승인한 방향은 기존 픽셀 RPG 오피스를 다듬는 것입니다.

- 제품: MDRM 릴리스와 패치 이력을 보여주는 작은 오피스
- 성격: 아기자기함, 차분함, 기술적인 정확함
- 세계: 파랑·크림색의 픽셀 개발실, 기존 Kenney 모델과 두 로컬 글꼴
- 주인공: 움직이는 1층 오피스와 패치 이력이 쌓이는 지하 묘역
- 고유 디테일: 1F/B1 층을 오가며 묘비에서 패치 기록을 찾는 경험

전체 화면 감사에서 패널마다 반복되는 밝은 3px 테두리, 장면 뒤의 보라색 광원 효과, 6~10px 보조 글자, 과도한 영문 대문자 라벨, 제각각인 여백, 모바일의 빈 활동 로그 영역, 동시에 나타나는 말풍선 10개를 확인했습니다.

수정은 간격 → 색 → 아이콘 → 문구 → 글자 → 배치 → 세부 요소 → 장면 → 움직임 순으로 적용했습니다. 간격은 4px 단위, 패널 안쪽은 16px, 일반 보조 글자는 12px로 맞췄습니다. 색상은 기존 파랑 계열을 차분하게 낮추고 크림색 글자와 금색 선택 상태를 유지합니다. 픽셀 아이콘은 기존 세트에서 16px 크기로 통일합니다. 제목은 제품명을 그대로 쓰고 설명은 릴리스·패치 기록이라는 실제 목적을 드러냅니다. 네 정보 탭과 섹션 순서도 유지합니다.

기존 디자인의 정체성인 픽셀 모서리와 두 글꼴은 유지합니다. 로컬 한글 글꼴의 실제 400/700 두 굵기를 사용하며, 3D 벽·묘비 표면에 투영하는 글자는 세계 좌표 비율을 유지합니다. 외부 이미지·에셋·폰트는 추가하지 않았습니다.

개발진·용사·AGENT 이름표는 캐릭터에 마우스를 올렸을 때만 표시합니다. 마우스가 떠나거나 드래그·층 이동 중이면 숨깁니다. 터치 화면에서는 이름표가 고정되지 않으며 캐릭터나 에이전트 목록을 눌러 역할과 현재 상태를 확인할 수 있습니다. 방 이름·몬스터 등급·묘비 이름은 유지합니다.

업무 말풍선은 동시에 최대 3명까지 표시합니다. 현재 말하지 않는 개발진·회의 담당 중 화자를 무작위로 고르고, 새 대사는 0.9~1.8초의 무작위 간격으로 시작합니다. 한 대사는 2.8초 동안 유지하며 3명 모두 말하는 중이면 빈자리가 생길 때까지 새 대사를 시작하지 않습니다. 같은 캐릭터의 중복 표시와 즉시 반복 선택을 피하고, 대사 큐 없이 말하는 순간의 현재 상태를 사용합니다. 격려는 8~11초 간격을 기준으로 가능한 차례에 나오고, 담당자는 잠시 걸음을 멈추고 확성기를 듭니다.

전투 알림은 별도 한 개로 유지해 업무 대사를 끊지 않습니다. 화면에는 업무 대화 최대 3개와 행동 알림 한 개까지 표시합니다. `공격!`과 `방어!`는 행동 순간에 나오며 전투 종료 시 제거됩니다. 직접 선택한 설명도 3명 제한 안에서 즉시 표시하고 4.5초 읽을 수 있습니다. 자리가 모두 찼다면 종료가 가장 가까운 대사를 교체합니다. 모션 줄이기에서는 전투 알림을 지우고 현재 업무 말풍선들을 고정합니다. 역할 팻말은 마우스 오버 때만 보이며 지하층에서는 1층 말풍선을 숨깁니다.

`npm run test:polish`로 마우스 오버 팻말, 자동 말풍선 제한, 직접 선택, 모바일 터치, 모션 줄이기, 대비·키보드 초점·반응형 넘침을 확인합니다. 검증 결과와 미검증 환경은 `docs/validation.md`에 기록합니다.

디자인 감사 및 개선 절차는 Damir Sokolovsky ([@heydamir](https://x.com/heydamir))의 [unslop](https://heydamir.design/unslop), CC BY 4.0에 기반합니다.


## java4shell 출현 · 2026-11-18

사용자가 보고한 `java4shell`을 미해결 이슈로 추가했습니다. 기존 게임의 치명 등급 드래곤 표현을 사용하며, 실제 취약점의 공식 심각도·CVE를 판정한 것은 아닙니다. 패치 버전과 일정은 지정하지 않았으므로 화면에는 **패치 대기 중**으로 표시합니다. 현재 운영 버전과 기존 v4.7.4의 패치 기록은 그대로입니다. 서버실 균열과 방어 전투가 다시 활성화되며, 새 무덤은 이 이슈가 발행 완료된 릴리스에 포함될 때 생성됩니다.


## 말풍선 복원 · 2026-11-18

이전 픽셀 테두리·크기·그림자로 복원했습니다. 후속 요청에 따라 역할 팻말은 마우스 오버 때만, 업무 대화는 랜덤하게 최대 3명까지, 전투 알림은 별도로 표시하며 대기 큐는 사용하지 않습니다. 층 이동은 유지합니다.

개발진은 취약점 분석, 패치 개발, 회귀 테스트, 빌드·검수로 역할을 나눴습니다. 현재 미해결 이슈인 java4shell 대응과 기존 패치 재검증을 말하며, 릴리스 관리·운영 지원·일정 독려·회의실 대사도 같은 상황을 따릅니다. 패치 버전·일정이 없을 때는 일정 미정으로 표시하고, 실제 수정 완료나 발행을 가정하지 않습니다. 업무와 대사는 연출입니다. `npm run test:polish`는 현재 대사, 말풍선 동시 표시 제한, 모션 줄이기와 반응형 화면을 검증합니다.
